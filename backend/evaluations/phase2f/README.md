# Phase 2F deliverables and reproduction

Start with [REPORT.md](REPORT.md), [MATHEMATICAL_AUDIT.md](MATHEMATICAL_AUDIT.md)
and [ABLATION_PLAN.md](ABLATION_PLAN.md). The latter is a proposal only.
[Figures](figures/CAPTIONS.md) include seven SVG/PDF pairs. All six reward
components are **positive costs**; original reward is their negative sum.

The exact source/artifact inventory is [CHANGED_FILES.md](CHANGED_FILES.md).
[protocol.json](protocol.json) pins the18 replay selections and original input
hashes. [provenance.json](provenance.json) hashes every new artifact except itself
and the inventory, verifies original inputs, and records unchanged tracked sources.
[environment.json](environment.json) and `*_resources.json` record execution limits.

## Outputs

- `saved_episode_components.csv`:504 saved training/validation episodes; exact
  four-component totals, worst+eMBB residual and explicit bounds/nulls. Never
  interpret a null as zero. `saved_component_distributions.csv` summarizes them.
- `candidate_ordering.csv` / `ordering_comparisons.csv`:24 balanced validation
  candidate means /276 pair differences (all numeric deltas are **A minus B**).
- `reward_ticks.csv.gz`:53,820 paid1ms ticks; `reward_intervals.csv.gz`:5,382
  ten-tick transitions; `ue_intervals.csv.gz`:43,056 UE snapshots. These are the
  selected diagnostic validation sample, not recovered training interval logs.
- `replay_summaries.jsonl.gz`, `replay_checks.json`:18 original outcome/control
  equivalence checks and unchanged parameters/update counts.
- `replay_component_totals.csv`, `interval_component_distributions.csv`:six-part
  costs, separated by grid and extra diagnostic replay roles. Distributions include
  mean/median/p95/max/zero fraction; quantiles are descriptive, not confidence bounds.
- `temporal_and_resource_diagnostics.csv`, `failure_credit_timing.csv`,
  `failure_timing_histogram.csv.gz`:saturation, consecutive duration, reserve
  headroom/observed unused allocation and arrival-to-first-failure lags.
- `strong_history_carry_examples.csv`,
  `service_improvement_with_history_examples.csv`,
  `successful_service_historical_runs.csv`:trace-selected historical carry cases.
- `actual_terminal_intervals.csv`, `terminal_checkpoint_summary.csv`,
  `observed_prefix_accounting.csv.gz`:actual terminal charges versus read-only
  prefix accounting; all original physical episodes remain3s.
- `switch_cost_associations.csv`:observed switch/stay associations, not interventions.
- Logs/resource reports retain commands, elapsed time, sampled peaks and exit status.

## Safe reproduction

Run from repository root in the existing Python environment. First inspect current
RAM/CPU utilization and choose up to four currently suitable allowed CPUs; the
archived runs used6,7,11,14. Do not blindly reuse a now-busy CPU assignment. The
guard sets affinity, disables CUDA, limits numerical threads, monitors the complete
launched process tree and stops at2.5GiB RSS or low system available RAM. The RSS
watchdog is **not a hard memory cap**. No parallel pytest/training workers.

Use a new output directory so archived measurements are preserved. Set
`AUDIT_OUT=/tmp/phase2f-reproduction` and `AUDIT_CPUS=6,7,11,14` only after checking
current utilization. Commands are sequential:

```bash
free -h
ps -eo pid,psr,pcpu,rss,comm --sort=-pcpu | head -16
mkdir -p "$AUDIT_OUT"
cp backend/evaluations/phase2f/protocol.json "$AUDIT_OUT/protocol.json"
python backend/tools/phase2b_guard.py --cpus "$AUDIT_CPUS" \
  --warning-gib 2 --stop-gib 2.5 --report "$AUDIT_OUT/saved_resources.json" \
  -- python backend/tools/phase2f_audit.py saved --output "$AUDIT_OUT"
python backend/tools/phase2b_guard.py --cpus "$AUDIT_CPUS" \
  --warning-gib 2 --stop-gib 2.5 --report "$AUDIT_OUT/replay_resources.json" \
  -- python backend/tools/phase2f_audit.py replay --output "$AUDIT_OUT"
python backend/tools/phase2b_guard.py --cpus "$AUDIT_CPUS" \
  --warning-gib 2 --stop-gib 2.5 --report "$AUDIT_OUT/report_resources.json" \
  -- env MPLCONFIGDIR=/tmp/phase2f-mpl python backend/tools/phase2f_report.py \
  --output "$AUDIT_OUT"
```

Do not regenerate or edit the frozen protocol to choose better cases. The `freeze`
command creates the prescribed selection only when no protocol exists; normal
reproduction copies the committed one. Input hashes are verified before replay.
Report generation needs Matplotlib/NumPy but does not run the simulator. Markdown
decision documents and provenance are authored deliverables, not regenerated by
these commands. The reporter also generates `terminal_checkpoint_summary.csv`
from the saved records (split/regime/episode count, terminal mean/max and maximum
nonzero-cost share).

Focused and nontraining regression commands (also run sequentially):

```bash
python backend/tools/phase2b_guard.py --cpus "$AUDIT_CPUS" \
  --warning-gib 2 --stop-gib 2.5 --report "$AUDIT_OUT/focused_tests_resources.json" \
  -- python -m pytest backend/tests/test_phase2f.py -q
python backend/tools/phase2b_guard.py --cpus "$AUDIT_CPUS" \
  --warning-gib 2 --stop-gib 2.5 --report "$AUDIT_OUT/regression_resources.json" \
  -- python -m pytest backend/tests -q \
  -k 'not actual_updates_bounded and not real_causal_learning and not episode_resets_no_leaked_exposure and not actual_sequential_controllers_training and not actual_matched_learning'
```

Seven tests are deliberately excluded because they execute training; no claim is
made that they were rerun. Regression includes the six new audit tests. Pytest's
real instrumentation test uses one frozen checkpoint for two short16-interval
runs and checks identical controls, physical UE metrics and exact reward sums.
Do not run actual training or change the reward for this audit.
